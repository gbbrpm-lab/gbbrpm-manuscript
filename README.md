# GBBRPM Cross-Domain Thesis Manuscript

This directory contains the reproducible LaTeX manuscript for the **Graph-Based Bounded Risk Propagation Model (GBBRPM)** thesis. The manuscript evaluates one frozen propagation architecture across three directed-network domains: drainage, software dependency, and electrical networks.

The project is intended to be edited in VS Code, tracked with Git, built locally, and optionally imported into Overleaf.

## Current manuscript structure

- **Chapter I — Introduction:** Establishes the comparative network-risk problem, research questions, objectives, scope, and conceptual framework.
- **Chapter II — Review of Related Literature:** Provides a literature-only synthesis of local assessment, graph prioritization, propagation-model families, state semantics, aggregation, dependence, parameterization, and the architectural research gap.
- **Chapter III — Methodology:** Defines the controlled architecture-validation protocol and the drainage, software-dependency, and electrical-network evaluation methods.
- **Chapter IV — Results and Discussion:** Reports the controlled results, robustness and scalability analyses, reconvergence diagnostic, SWMM comparison, software case, and electrical baseline case.
- **Chapter V — Summary and Conclusion:** Separates the conclusions supported by each evidence source and keeps unsupported field or event-validation claims explicit.
- **Chapter VI — Recommendations:** Lists the empirical data, validation, dependence-handling, and model-extension work that remains.
- **Appendix A — Worked Example:** Gives a fully traced calculation of the generic GBBRPM core architecture using controlled dimensionless inputs.

## Evidence boundaries

The three domain cases do not provide equivalent forms of validation:

- **Drainage:** controlled synthetic networks and SWMM-based hydraulic comparison; operational field data remain pending.
- **Software dependency:** real Express dependency topology and vulnerability-advisory evidence; supports structural and sensitivity findings, not observed incident prediction.
- **Electrical network:** real topology and normal-operation baseline measurements; event-centered validation remains pending because the available data do not cover the requested November 13 switching windows.

GBBRPM produces a bounded, non-probabilistic comparative risk index. It is not presented as a calibrated failure probability, hydraulic simulator, universal predictor, or completed electrical event model.

## Requirements

### Windows

- [MiKTeX](https://miktex.org/download)
- [Strawberry Perl](https://strawberryperl.com/) for `latexmk`
- [VS Code](https://code.visualstudio.com/)
- [LaTeX Workshop](https://marketplace.visualstudio.com/items?itemName=James-Yu.latex-workshop)
- Python 3 with `matplotlib` and `pandas` only when regenerating the included Chapter IV plots

After installation, restart VS Code and verify the toolchain in PowerShell:

```powershell
perl --version
pdflatex --version
latexmk --version
```

## Build the manuscript

Open the project directory in VS Code and build `main.tex` with LaTeX Workshop, or run:

```powershell
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
```

The generated document is `main.pdf`. `main.tex` is the root file.

Clean auxiliary build files with:

```powershell
latexmk -c
```

To verify reproducibility, clone the repository into a new directory and build it again without copying files from the original working directory.

## References and formatting

- In-text sources use LaTeX author–date citation commands through `natbib`.
- The reference list is organized alphabetically in APA-style presentation.
- `main.tex` applies the available CITC body requirements, including A4 paper, the binding margin, paragraph indentation, single spacing, chapter headings, caption placement, equation labels, and page-number positioning.
- Palatino is used as the closest installed TeX-compatible substitute for Book Antiqua. Confirm whether the exact proprietary font is required for final submission.
- Preliminary pages are intentionally incomplete because their official template and required approval information were not provided with the body-formatting guideline.

## Use with Overleaf

1. Download or create a ZIP containing the complete project directory.
2. In Overleaf, choose **New Project → Upload Project**.
3. Upload the ZIP.
4. Confirm that `main.tex` is selected as the main document.
5. Compile with pdfLaTeX.

Overleaf is optional; the Git repository remains the reproducible source of truth.

## Git guidance

Commit manuscript sources, scripts, input data required for regeneration, and final approved figures or tables. Do not commit LaTeX auxiliary files such as `.aux`, `.log`, `.fls`, `.fdb_latexmk`, `.out`, or `.synctex.gz`.

Before pushing a manuscript revision:

```powershell
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
git status
git add .
git commit -m "Update thesis manuscript"
git push
```

This workflow keeps equations native to LaTeX, makes chapter and section numbering automatic, preserves traceable cross-references and citations, and allows each manuscript revision to be reproduced from version-controlled sources.
